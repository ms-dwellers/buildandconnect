# Mascot fieldbook

The web app follows the neighbourhood fieldbook direction: cream paper, pine
ink, a dotted mint board, tactile cards, and a small pixel mascot. Kinopio is a
reference for warmth and visible relationships, not a source of copied artwork
or a reason to turn onboarding into a freeform canvas.

## Surfaces

- **Account entry:** direct sign-in stays in place. A pair of paper notes links
  personal learning with community needs, beside the supplied happy mascot.
- **Navigation:** the base mascot is a compact brand mark. Current links use an
  underline instead of filled decorative pills.
- **Dashboard:** the mascot accompanies the primary action. Project cards show
  commitment alongside their purpose; supporting career navigation is quieter.
- **Career projects:** requirement selection and practice links remain real
  data. Connected dots mark concrete activities, not scores or completed skills.
- **Project detail:** the project title is the page heading. Time, compensation,
  and response controls sit together; on mobile they precede the complete brief.
  A scope link remains visible, and match numbers are secondary disclosure.

The same coss-ui components, confirmation dialogs, access checks, and semantic
theme tokens remain in use. Nothing automatically expresses interest, publishes
a project, changes account roles, or claims a completed outcome.

## Mascot assets and motion

Eight supplied GIFs came from `origin/main` at `1a039d2e`, under
`public/assets/mascots/`. The original assets are unchanged. Their first frames
are generated by `bun run assets:mascot`, without an image-processing dependency.

`components/mascot.tsx` is decorative, has reserved dimensions, and uses crisp
pixel rendering. Its shared feedback mapping is:

| App state         | Character | Motion                                   |
| ----------------- | --------- | ---------------------------------------- |
| Idle              | Base      | Loops while animations are enabled       |
| Loading or saving | Running   | Loops until the operation ends           |
| Success           | Happy     | Plays for four seconds, then holds still |
| Recoverable error | Crying    | Plays for four seconds, then holds still |

Loading controls and skeletons use the running character. Error alerts use the
crying character without removing their message or retry action. Existing
success/error notifications use the corresponding character; no additional
success notifications are invented just to show an animation.

The header's **Mascot animations** toggle pauses every character, including
those already moving. Its browser-local preference survives navigation and
reloads; no profile, credentials, or drafts are stored with it. If browser storage
is blocked, the toggle still works for the current page. Device reduced-motion
settings always win and use the still image without downloading animated GIFs.

The imported assets are the only remote changes included in this design pass.
The fetched branch also contains a backend migration and iOS work; those remain
on `main@origin`, outside this local web-design change. No iOS tools are needed.
